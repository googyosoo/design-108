# 01. 웹앱·웹페이지 공통 제작 표준 (재사용용)

> **용도**: 이 문서는 「DesignMind 108」뿐 아니라 **앞으로 만드는 모든 교육용 웹앱·웹페이지**에 그대로 복사해 쓰는 공통 기준입니다.
> **역할**: Claude(계획·검수) · Antigravity(실행) · 선생님(승인) — 세 주체가 같은 기준으로 판단하기 위한 "약속".
> **우선순위**: 프로젝트 계획서(00_)의 지시 > 이 문서 > 에이전트의 일반 습관.
> **버전**: v1.0 (2026-10-17)

## 1. 반응형 레이아웃

### 1.1 브레이크포인트

| 이름 | 폭 | 내비게이션 | 카드 그리드 | 본문 최대폭 |
|---|---|---|---|---|
| `mobile` | 0–639px | 하단 탭바(최대 5개) | 1열 | 100% (좌우 여백 16px) |
| `tablet` | 640–1023px | 하단 탭바 | 2열 | 680px |
| `desktop` | 1024–1439px | 좌측 사이드바(240px) | 3열 | 760px |
| `wide` | 1440px+ | 좌측 사이드바 | 4열 | 760px (본문), 그리드는 1280px |

### 1.2 레이아웃 규칙
- **가로 스크롤 금지**: 어떤 폭에서도 `body`에 가로 스크롤이 생기면 P0 결함. (표·코드블록은 자체 `overflow-x: auto` 컨테이너 안에서만 스크롤)
- **안전 영역**: 하단 탭바는 `padding-bottom: env(safe-area-inset-bottom)` 적용 (아이폰 홈 인디케이터).
- **고정 요소 최소화**: 상단바 56px + 하단 탭바 64px 외에 화면을 가리는 고정 요소 금지.
- **엄지 영역**: 모바일에서 주요 버튼(CTA)은 화면 하단 1/3에 배치 (피츠의 법칙).
- **이미지**: 모든 `<img>`에 `width`/`height` 또는 `aspect-ratio` 지정 → 레이아웃 흔들림(CLS) 방지.

## 2. 타이포그래피

### 2.1 글꼴
- 기본: **Pretendard Variable** (OFL 라이선스, CDN: `cdn.jsdelivr.net/gh/orioncactus/pretendard` — 정확한 버전 고정)
- 대체 스택: `"Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif`
- 숫자(번호·점수): `font-variant-numeric: tabular-nums;`

### 2.2 크기 스케일 (rem 기준, 1rem = 16px)

| 토큰 | 크기 | 줄간격 | 굵기 | 용도 |
|---|---|---|---|---|
| `--text-display` | 2.25rem (36) / 모바일 1.75rem | 1.25 | 800 | 홈 헤드라인 |
| `--text-h1` | 1.75rem (28) / 모바일 1.5rem | 1.3 | 700 | 페이지 제목 |
| `--text-h2` | 1.375rem (22) | 1.4 | 700 | 섹션 제목 |
| `--text-h3` | 1.125rem (18) | 1.5 | 600 | 카드 제목 |
| `--text-body` | 1rem (16) | 1.7 | 400 | 본문 |
| `--text-small` | 0.875rem (14) | 1.6 | 400 | 보조 설명 |
| `--text-caption` | 0.8125rem (13) | 1.5 | 500 | 캡션·칩 (최소 크기) |

### 2.3 한글 가독성 규칙
- `word-break: keep-all; overflow-wrap: anywhere;` — 단어 중간 줄바꿈 방지
- 본문 단락은 **최대 3~4문장**, 문장은 **최대 50자** 권장
- 강조는 **굵게**만 사용 (밑줄은 링크 전용, 기울임은 영문 용어 전용)
- 영문 병기: `쿨레쇼프 효과 Kuleshov Effect` 처럼 한글 뒤에 작게(`--text-small`, muted 색)

## 3. 색 (디자인 토큰)

> 모든 색은 CSS 변수로만 사용. 컴포넌트 안에 `#hex` 직접 작성 금지.
> 아래 값은 WCAG 대비를 **계산으로 확인한 값**입니다(괄호 = 배경 대비).

### 3.1 라이트 모드

| 토큰 | 값 | 용도 | 대비 |
|---|---|---|---|
| `--color-bg` | `#FAF8F4` | 페이지 배경(따뜻한 종이색) | — |
| `--color-surface` | `#FFFFFF` | 카드·시트 | — |
| `--color-ink` | `#1E2126` | 본문·제목 | 15.2:1 |
| `--color-ink-muted` | `#585E68` | 보조 텍스트 | 6.2:1 |
| `--color-line` | `#E6E1D8` | 구분선·테두리 | 장식용 |
| `--color-focus` | `#1D6AA8` | 포커스 링(2px + 2px offset) | 5.4:1 |
| `--color-success` | `#12735F` | 정답·완료 | 5.4:1 |
| `--color-danger` | `#B3304A` | 오류·위험 | 5.8:1 |

### 3.2 다크 모드 (`prefers-color-scheme: dark` + 수동 토글 `[data-theme="dark"]`)

| 토큰 | 값 | 대비 |
|---|---|---|
| `--color-bg` | `#14161A` | — |
| `--color-surface` | `#1C1F24` | — |
| `--color-ink` | `#ECEEF1` | 15.6:1 |
| `--color-ink-muted` | `#A6ACB6` | 7.9:1 |
| `--color-line` | `#2C3038` | 장식용 |

### 3.3 색 사용 규칙
- **색만으로 의미 전달 금지**: 정답/오답은 색 + 아이콘(✓/✕) + 텍스트를 함께.
- 강조색은 **한 화면에 1개 계열**만 (대비의 법칙 — 여러 색을 강조하면 아무것도 강조되지 않음).
- 큰 면적에는 채도 낮은 색, 작은 포인트에만 진한 색.

## 4. 간격·모양·그림자

| 토큰 | 값 | 규칙 |
|---|---|---|
| `--space-1`…`--space-10` | 4, 8, 12, 16, 20, 24, 32, 40, 56, 72px | **4의 배수만** 사용 |
| `--radius-sm` / `md` / `lg` / `full` | 8 / 12 / 20 / 9999px | 버튼 md, 카드 lg, 칩 full |
| `--shadow-1` | `0 1px 2px rgb(0 0 0 / .06), 0 1px 1px rgb(0 0 0 / .04)` | 기본 카드 |
| `--shadow-2` | `0 8px 24px rgb(0 0 0 / .10)` | 떠 있는 시트·모달 |

- **근접의 법칙 적용**: 관련 요소 간격 ≤ 8px, 그룹 간 간격 ≥ 24px.
- 섹션 사이 여백은 `--space-8`(40px) 이상 — 화이트 스페이스로 고급감·집중도 확보.

## 5. 컴포넌트 규칙 (모든 컴포넌트가 지켜야 할 "상태 6종")

모든 인터랙티브 컴포넌트는 아래 6가지 상태를 **모두** 디자인·구현해야 합니다.

| 상태 | 규칙 |
|---|---|
| 기본 default | 토큰 색 사용 |
| 호버 hover | 마우스 기기에서만 (`@media (hover: hover)`) |
| 포커스 focus-visible | 2px 포커스 링, 절대 `outline: none` 단독 사용 금지 |
| 눌림 active | `transform: scale(.98)` 수준의 미세 피드백 |
| 비활성 disabled | 투명도 .45 + `aria-disabled` + 이유 툴팁 |
| 로딩 loading | 스피너 대신 **스켈레톤** 또는 진행 문구 ("분석 중… 약 10초") |

### 5.1 필수 공통 컴포넌트 목록
`Button`(primary/secondary/ghost, 최소 높이 44px) · `IconButton`(44×44, `aria-label` 필수) · `Chip`(필터, 토글형) · `Card` · `Tabs` · `BottomSheet`(모바일) / `Dialog`(데스크톱) · `Toast`(4초 자동 닫힘, `role="status"`) · `EmptyState`(일러스트 + 한 줄 안내 + 다음 행동 버튼) · `ErrorState`(무슨 일이/왜/어떻게 3줄) · `Skeleton` · `ProgressRing` · `SearchInput`(지우기 버튼 포함)

### 5.2 문구(마이크로카피) 규칙
- 버튼은 **동사로 끝나기**: "확인" ❌ → "체험해 보기" ✅
- 오류 메시지는 **사용자를 탓하지 않기**: "잘못 입력했습니다" ❌ → "이미지는 10MB 이하만 올릴 수 있어요. 크기를 줄여 다시 시도해 주세요" ✅
- 빈 화면에는 항상 **다음 행동** 제시: "아직 저장한 효과가 없어요 → [도감 둘러보기]"
- 교사·학생 모두 읽으므로 **존댓말 해요체** 통일

## 7. 접근성 체크리스트 (WCAG 2.2 AA 요약)

- [ ] 모든 이미지·SVG에 `alt` 또는 `aria-label` (장식용은 `alt=""` / `aria-hidden="true"`)
- [ ] 제목 계층 `h1 → h2 → h3` 건너뛰지 않음, 페이지당 `h1` 1개
- [ ] 랜드마크: `<header> <nav> <main> <footer>` 사용, "본문 바로가기" 링크
- [ ] 키보드: Tab 순서 = 시각 순서, 모달은 포커스 가두기 + Esc 닫기 + 닫으면 원래 위치로 포커스 복귀
- [ ] 폼: 모든 입력에 `<label>`, 오류는 `aria-describedby`로 연결
- [ ] 동적 변화(퀴즈 결과, 토스트)는 `aria-live="polite"`
- [ ] 200% 확대해도 기능 손실 없음
- [ ] 드래그만으로 되는 기능 금지 → 버튼·슬라이더 대안 제공 (WCAG 2.5.7)
- [ ] 슬라이더는 `<input type="range">` 기반 + 현재값 텍스트 표시
- [ ] 언어 표시: `<html lang="ko">`, 영어 문장은 `lang="en"`

## 9. 코드 규칙 (선생님 스타일 고정)

- 변수·함수명: 의미 있는 영어, **동사로 시작** (`generateFeedback`, `filterEffectsByPurpose`)
- 들여쓰기 **2칸**, `async/await` 선호, 주석은 "왜"만 짧게
- **UI 로직과 데이터 로직 분리**: `src/lib/`(순수 함수) ↔ `src/components/`(화면)
- 컴포넌트 1파일 1컴포넌트, 200줄 넘으면 분리 검토
- 요청 범위 밖 리팩토링 금지, 불필요한 파일·폴더 생성 금지, 과잉 설계 금지
- 의존성은 꼭 필요한 것만. 추가 시 `docs/DECISIONS.md`에 "무엇을/왜/대안" 3줄 기록
- `package.json` 버전은 **정확한 버전으로 고정**(`^` 제거) — 재현 가능한 빌드
- 비밀값(API 키)은 **서버 환경변수에만**. 프런트 코드·Git에 절대 포함 금지 (`.env`는 `.gitignore`)

## 10. 학생 데이터·개인정보

- **로그인·회원가입 없음**이 기본값. 개인 학습 기록은 브라우저 `localStorage`에만 저장(모든 접근은 `try/catch`, 실패해도 앱 정상 동작).
- 이름·학번·얼굴 사진 등 **개인식별정보 수집 금지**.
- AI 분석용 업로드 이미지는 **서버에 저장·로그 기록 금지**, 분석 후 즉시 폐기. 화면에 "업로드 전 학생 얼굴·이름이 보이지 않는지 확인하세요" 안내.
- 외부 분석 도구(GA 등) 기본 미사용. 필요 시 선생님 승인 후 추가.
- 학교 정책과 충돌 시 학교 정책이 우선.

## 13. 새 프로젝트에 이 문서를 재사용하는 방법

1. 새 프로젝트 폴더의 `docs/`에 이 파일을 그대로 복사한다.
2. 3장의 색 토큰 중 **브랜드 강조색만** 바꾼다 (바꾼 뒤 대비 4.5:1 재확인).
3. 새 계획서(00_)의 첫 줄에 "공통 표준: `docs/01_WEBAPP_STANDARDS.md` 준수"라고 적는다.
4. Antigravity 첫 지시에 "01_WEBAPP_STANDARDS.md를 먼저 읽고 모든 작업에 적용"을 포함한다.
5. 프로젝트 고유 예외가 있으면 이 파일을 고치지 말고 계획서에 "표준 예외" 절을 만들어 기록한다.
